# 《主线任务呢？》：已认可的角色动画案例

这是角色故事分支的成功修改经验，不是所有音乐视频的默认模板。2026-11-11 用户补充了动态歌词、图形和贴纸 MV 参考；新歌先按 [轻量 MV：参考与表达方法](lightweight-mv-references.md) 选择表达。下述 v1 的问题是事件与节奏不足，不能据此否定所有文字或界面动画。

## 采用哪个版本

用户 2026-11-10 认可的是 **v2 的角色画风与故事 + v4 的镜头、节奏和停顿**。采用后传的《主线任务呢_ (2).mp3》，成片 114.5 秒、1920×1080、30fps。角色为程序员“我”与电脑里的 ChatGPT，不使用 Claude 宠物。

- v1：界面、文字和任务图把事情说明白了，但用户认为死板，像信息讲解。
- v2：加入同一程序员的反应姿势与电脑桌场景，方向获认可；用户指出人物仍像切换表情的静态图。
- v3：尝试连续动作生成，但 HeyGen 当时返回额度不足，未生成视频；随后骨骼实验过重，用户明确停止。不是获认可成片，也不是以后要复用的制作路线。该次额度状态不代表以后账号仍无额度。
- v4：从 v2 继续，只调整镜头切换、动作节奏、停顿与少量界面状态，获用户确认“这版可以了”。没有使用骨骼动画或新生成的视频片段。

## 可复用的剪辑经验

1. **让画面演事情。** 屏幕里的动作和人的反应构成因果。文字主要承担歌词和必要对话，不用解释性标题代替剧情。
2. **先看动作，再看反应。** 目录被重排、搜索逻辑空白、任务拖到明天，先给动作特写，再切人物近景；需要重新建立关系时回全景。
3. **给打断留蓄势。** 本曲约 52.37–52.8 秒先看 Agent 还想继续，随后切举掌喊停；回全景时按钮由“暂停 Agent”改成“已暂停”，动作有结果。
4. **笑点别抢反应。** 三次查询返回同样的数据后，让“目前使用的是模拟数据”说完；106.8–107.45 秒愣住，再切捂脸全景。短停顿由原曲空隙承载，不修改音轨。这些时间只适用于本曲。
5. **动静有区别。** 去掉人物持续随音乐上下抖动，保留动作开始时的小幅强调，随后停稳。静止可以表达等待和无语；重点是停在哪里、停多久，以及前后发生什么。
6. **间奏也有戏。** 用等待搜索、检查交付、看到空代码与人物反应承接间奏，不误判为漏词，也不塞满无关装饰。
7. **切镜时保证可读。** 字幕在重构图之后独立绘制。屏幕特写直接复用 UI 图层，排除前景杯子和掉落道具，避免放大后出现裁断碎片。

保留题材自由：复用的是叙事和剪辑方法，不是这些台词、角色、电脑桌或精确秒数。发现角色图集有相邻姿势碎片时，核对单帧取样区域；本例修正了第二格右侧侵入，不把这个裁切尺寸用于别的素材。
