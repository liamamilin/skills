# 轻量 MV：让歌词、图形和界面演事情

适用于用户提供参考视频、要求减少人物制作，或制作当前这类 AI 自我吐槽歌。先选能承载歌曲的表达，不把人物素材作为启动条件。角色故事仍可采用，尤其是修改用户已经认可的作品。

## 在生成素材之前选路线

- **动态歌词＋图形隐喻**：关键词鲜明、抽象矛盾多，例如“优化、分层、迷宫”。让字、线、门、补丁成为动作主体。当前《我还在优化》优先采用这一方向。
- **界面事件＋持续状态**：有具体任务与可见结果，例如删空格、改按钮。界面要发生阻挡、复制、堆叠、耗尽或反转，不做静态产品讲解。
- **贴纸拼贴／角色故事**：角色反应确实增加情绪或用户已有认可素材时采用。少量关键姿势加构图和剪辑即可；不因参考有人物就自动扩建角色系统。

选一个主视觉语法，允许局部混合。图形能讲清的镜头直接用代码／矢量；不先生成大批角色、表情或背景。已有素材保留，不因已经生成就强行使用。不复制参考作者的具体人物、歌词和整套画面。

## 从一句歌词到一个动作

先写“谁／什么发生什么变化，观众最后看见什么”，再选动效。每个乐句通常一个主事件，重音和句尾决定揭晓点；不按每个名词塞图标。

以下是《我还在优化》的迁移草案，尚未渲染，实际采用需跟随演唱时间：

| 歌词意象 | 可演动作 | 结果与节奏 |
| --- | --- | --- |
| 先把问题分层 | 一个“问题”字块拆成层，层层叠高 | 本来很小的事被堆大，停一拍让观众看清 |
| 十二种可能 | 一个答案入口分裂成多个分支 | 分支把“结果”挤到画外，突出结果消失而非要求读完所有选项 |
| 直路修成迷宫 | 同一路径不断长出弯折 | 出口仍可见却更难到达，后段再回收这条路 |
| 补丁花 | 补丁逐层覆盖同一缺口，再长成花 | 花盛开时缺口仍在；装饰与任务的反差可见 |
| 电脑合上 | 原本拥挤的界面向一道缝收拢 | 用歌中空隙停稳，不另剪断音乐制造停顿 |
| 先把门打开 | 堵住出口的字块撤开，门缝透光 | 与前面拥挤形成对比，结尾给通路和留白，不再添装饰 |

## 活泼来自变化，不是一直抖动

- 建立少量反复出现的母题，跨段落保留对象身份和状态。副歌复现时升级规模、方向或结果，末段反转同一母题；不要整段机械重播，也不用每次全换素材。
- 动作有进入、发展、落定。让“分层”真的分开、“循环”真的回到原处、“补丁”真的遮住对象；无关弹跳、随机缩放和转场不能替代语义动作。
- 重音处给变化，句尾留阅读和笑点停顿。音乐密时让镜头简单，桥段可减色、减元素、放慢动作；快慢与疏密的对比比持续高频更有效。
- 同屏一个主要注意点。歌词若已作主体且完整可读，不再重复烧录一遍；小字可以营造界面，但笑点不能依赖读清长日志或哈希。
- 统一字体、轮廓、色板与元素风格。主题变换优先用构图、明暗、尺寸、留白；不要拼贴多个互不相干的品牌徽标。所谓高级感落实为克制、可读与准确的画面隐喻，不等于堆光效。

## 怎么用于下一次制作

在既有项目记录中写明选中的路线、贯穿对象、素材需求和参考启发即可，不新建复杂管理系统。新路线先用本曲代表性的“主歌事件 → 副歌升级 → 停顿”连续片段判断节奏；这是整片生产的内部验证，不把小样冒充最终交付，也不要求用户再批分镜。有效后完成整片，检查重复副歌与结尾是否真正有变化。

若必须增加大量新素材或动画系统才能继续，先简化表达；保留骨骼动画禁用与不自动订阅的既有边界。实际对齐、原声、附加尾部口播、品牌身份和交付检查仍按 [视频制作](video-production.md)。只学习／更新 skill 时停在记录，不生成或投稿；用户暂停的作品继续暂停。
