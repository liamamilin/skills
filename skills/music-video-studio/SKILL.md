# 音乐视频创作

从用户已有的材料继续，交付其请求的创意、歌曲或成片。面向中文创作，题材和视觉形式不限于 AI、程序员或界面喜剧。

## 选择入口

- **没有 idea**：读 [创意与歌曲](references/ideas-and-mureka.md)，给 4–6 个具体且不同的候选，让用户选方向。每个候选包含故事、观众情绪、副歌钩子、三个可演画面、结尾；说明推荐依据，不承诺流量。
- **已有 idea / 歌词**：保留其核心表达，完善冲突、人物视角、情绪递进、可唱副歌与画面。已有明确选择或获授权直接制作时，不重复要求确认。
- **要生成歌曲**：同一参考说明中完成 Mureka 步骤。先准备完整歌词和音乐方向，再按用户授权生成，记录真实版本；用户试听、下载，再上传采用的文件。
- **已有歌曲与歌词 / 修改 MV**：直接读 [视频制作](references/video-production.md)。歌曲是主时钟；不要重新生成歌曲或重新开展创意筛选。缺少实际歌词时先利用已有资料或转写草案，只问影响制作的缺项。
- **提供参考视频 / 学习风格**：读 [轻量 MV：参考与表达方法](references/lightweight-mv-references.md)，实际查看代表段落及连续变化，区分看见的画面、制作推断和迁移方案。用户只要求学习或更新 skill 时，不恢复暂停的制作。
- **制作或优化封面**：读 [剧情封面](references/story-covers.md)。角色故事用剧情插画；动态歌词或图形 MV 用一个有冲突的核心视觉，不为封面额外造角色。不套通用“人物头像＋大标题＋标签”版式。
- **要投稿 / 修改已发布封面**：用户明确要求时全程走现有 workflow，不操控浏览器；读 [本机工具与投稿](references/local-runtime-and-publish.md)。B 站封面同时读 [剧情封面](references/story-covers.md) 的双比例适配：分别准备、上传并检查 4:3 与 16:9，核对实际采用文件，不能以生成了新图代替已更新投稿。本 skill 的默认终点仍是成片。

## 跨阶段约定

- 按作品主动触发。不创建栏目、调度、矩阵、定时发现任务，不恢复归档的 music_workshop 开发。
- 选择只发生在真实分岔处：用户没选创意时等待选择；歌曲生成后用户需要选听感；已选音频且要求制作时，继续做到成片，无需再批准分镜。
- 在一个版本目录保存 `project.json`：当前阶段、用户选择、歌词版本、源文件 SHA256、音乐方向、采用的歌曲、待完成事项、产物路径。新版本另存，保留源文件与失败尝试，不以聊天记忆代替作品记录。
- 先按歌曲与最新参考选择表达，再决定素材。当前这类 AI 歌曲优先考虑动态歌词、简单图形、界面事件与轻量拼贴；人物是可选分支，不先生成角色图集。已有获认可的角色作品继续在原版上优化，不强行改风格。文字可以成为动画主体，关键是动作、变化和反差，不能退化成逐页说明卡。
- 不走复杂骨骼动画、角色拆件绑定、逆向运动学或自建动画系统。优化已认可的视频时，先改镜头、动作节奏与停顿；视频模型额度不足不成为升级制作复杂度的理由。
- 画面先讲清发生了什么，再增加装饰。角色名称、品牌、图标和行为来自同一角色表；不要把 Claude 宠物当成 ChatGPT 的头像。多品牌同时出现时必须能看懂各自身份。
- 原始演唱可能改词、重复、漏唱，生成提示里的时长也不等于实际时长。以实际文件、实际演唱建立时间轴，不按歌词字数均分。
- 检查首尾是否有独立附加口播。按本用户偏好，可删除确认属于歌曲外的“当前内容由 AI 生成”等尾部口播，并保留音乐自然衰减；不能见到歌词里的 AI 就删除，也不能固定截掉末尾若干秒。不额外添加说明性片尾字幕。
- 生成、上传、人工听审、平台已公开分别记录。自动对齐、波形、抽帧、完整解码各有用处，都不能冒充完整试听或观看。
- 不主动扩展事实核实、来源审计或人工审批工作。用户要的是创意和画面；检查围绕歌词对应、角色逻辑、可读性和真实媒体交付。

## 可执行资源

- `scripts/prepare_project.py`：保留歌曲与歌词、建立源文件指纹、读取真实时长、转换对齐 WAV；不覆盖已有项目。
- `scripts/align_lyrics.py`：调用本地 Qwen3 forced aligner，输出原始词时间、句级时间和 SRT。模型位置由参数提供，听审状态保留为未完成。
- `scripts/check_video.py`：完整解码、音画时长、字幕区间和角色绑定检查；可比较保留区间的音频。它不是审美或听感验收。
- `assets/blue-button-example/`：蓝按钮历史成片的可运行 Python 渲染源码、宠物资产、角色表与时间码。只用于学习具体动作/复现蓝按钮；新作品需要自己的故事、时钟和资产，不替换歌词后硬套。
- [轻量 MV：参考与表达方法](references/lightweight-mv-references.md)：动态歌词、界面喜剧、贴纸拼贴及参考学习时阅读；记录实际观察、路线选择和歌词到动作的转换。
- [主线任务：动画与剪辑经验](references/main-quest-lessons.md)：已认可的角色动画分支；修改该类作品或处理“像切表情／太复杂”的反馈时阅读，不作为所有新歌的固定起点。
- [蓝按钮案例与踩坑](examples/blue-button-lessons.md)：在复用风格或修改旧作品时阅读。

## 完成标准

创意阶段有可选择的具体方案；歌曲阶段有实际生成结果或清楚的外部等待状态；视频阶段有真实可播放 MP4、封面、完整字幕、分镜/剪辑记录、可再次运行的源码和素材、技术检查结果；使用人物或品牌化身时附角色绑定记录。交付时优先给用户成片，简要说明关键改动和未完成的听审范围。
